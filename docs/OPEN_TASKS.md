# 可接手任务

以下是建议任务，没有假定已有认领人。建议一项 PR 聚焦一个可验证问题；无需机身也能先完成局部审查和测试。

## T1 UI 取消删除与失败反馈

起点：`lut_events_owner.c`，原厂任务管理器取消虚调用 `0x3209b18–0x3209b28`，删除／重置入口见源码地图。

目前后端已有挂接。缺少真实 UI 返回键／弹窗生产者、任务外围 model 记账、失败返回是否被调用者消费的证据；不能把直接调用测试当作 UI 闭环。

验收：给出可追溯事件链；在实际生产者入口注入确认／取消／超时／重复事件；证明失败不继续报告成功，删除拒绝不被后续步骤忽略。保留服务替身说明和正常路径对照。

## T2 共享缓冲所有权与其他读者

起点：`lut_all_readers.h`、`lut_events_native_snapshot.h`、两个外部调用者 `0x6f5d84`／`0x6f5de6` 及低层数据构造器。

验收：记录分配、转换、缓存、排队、DMA、释放的所有权链；排查直接／间接绕过现有入口的读取；证明描述捕获、缓存过期、失败及异步完成期间不会提前复用。直接 BL 列表不能当作完整调用图证明。

## T3 超时与硬件故障恢复

起点：`lut_events_owner.c`、`lut_dma_worker.c`、`lut_dma_capture.c` 和现有缺失／晚到回调测试。

验收：找到并验证真实驱动完成／中止约定；证明具体操作已经静止后才能解除对应隔离。覆盖永久缺失、晚到、重复、旧回调、提交失败和再次尝试。不得仅清软件故障位、凭服务返回 0 或未经验证的注销函数开放共享写入。

## T4 导入覆盖与设置生命周期

起点：`verify_menu.py`、`verify_dynamic_menu.py`、`verify_pp_setting_banks.py`、`verify_settings_commit.py`、`verify_pp_exclusion_queue.py`。

验收：导入／替换当前槽位、删除非当前槽位、照片／视频切换、MR、保存／恢复的完整入口测试；区分当前生效值与请求持久化值。记录实际文件写入、框架通知和 Backup 服务替身。

## T5 冷启动重启与安装设计

起点：两份 `build_lut_events_*`、`verify_lut_events_cp.py`、`native/`、旧事务接口。

验收：检查早期参数读取和栈余量；设计 AP/CP 不同步重启、WBI 和会话恢复；为增大 64 KiB 的 AP 文件提供新的同步／加载／恢复方案。先用本地文件和装载模型验证，不复用旧固定窗口安装包。

## T6 工具链与复现维护

起点：`tools/replay_offline.py`、源码快照清单和主机测试。

验收：保持精确输入校验；记录 Python/LLVM/Unicorn 版本；清楚区分主机测试与需要固件的机器码测试。可改进多平台支持、独立测试选择和报告可读性。不得通过禁用哈希或删掉失败用例让构建“通过”。

T1–T6 未完成前，项目仍是研究状态。真实 JPEG 像素、颜色和性能属于后续单独的受控硬件验证，不由当前离线 CI 代替。
